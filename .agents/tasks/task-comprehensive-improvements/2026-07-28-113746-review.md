# Comprehensive Angular SPA refactoring (v2)

This is the second review pass. Five of the seven v1 issues have been addressed: `ConfirmDialogComponent` now cancels its Subject on destroy, `ProductGalleryComponent` caches `validImages` in `ngOnChanges`, `DesignUploadComponent` stores and clears the timeout reference, all four placeholder pages gained `OnPush`, and `CartService.normalizeCartItem` documents its legacy fallbacks with a `MIGRATION` comment. The two remaining items (duplicated SCSS, mock-mode test coupling) were deemed acceptable trade-offs.

**Watch for:** The `MobileMenuComponent` registers a `keydown` event listener on its host element but never removes it on destroy, which leaks if the component is torn down while the menu is open (confirmed). The `ToastService` fires `setTimeout` per toast but holds no reference and provides no cancellation path; if the service is destroyed (e.g., during testing or SSR teardown), orphaned timers write to a dead signal (likely). The `ProductDetailComponent` — the largest orchestrator in the app — lacks `OnPush` despite all its child components using it, meaning the entire subtree gets default CD ticks from unrelated events (confirmed).

**Verdict**: APPROVED

## High-level view

The v1 lifecycle and memoization issues are resolved. The `ConfirmDialogComponent.ngOnDestroy` → `cancel()` path properly completes the Subject, and `ProductGalleryComponent` now computes images only when inputs change.

The `MobileMenuComponent` adds a `keydown` listener via `addEventListener` in `activateFocusTrap()` but only removes it through `deactivateFocusTrap()`, which is gated behind `AfterViewChecked` seeing `isOpen === false`. If Angular destroys the component while the menu is open (route guard, parent structural directive), the listener remains on the detached DOM node — a minor memory leak on each such occurrence.

The `ProductDetailComponent` orchestrates four `OnPush` children, uses signals internally, and subscribes to seven observables via `takeUntilDestroyed`. It is the ideal candidate for `OnPush` but was not updated in this change. Every parent change detection cycle triggers full evaluation of all template getters (`inStock`, `stockLabel`, `discountPercent`, `basePrice`, `estimatedUnitPrice`, `customizationSummary`) even when no relevant data changed.

## MobileMenu focus-trap listener lifecycle

```typescript
private activateFocusTrap(): void {
  this.focusTrapActive = true;
  this.elementRef.nativeElement.addEventListener('keydown', this.boundTrapFocus);
}

private deactivateFocusTrap(): void {
  this.focusTrapActive = false;
  this.elementRef.nativeElement.removeEventListener('keydown', this.boundTrapFocus);
}
```

`deactivateFocusTrap` is only called from `ngAfterViewChecked` when `!this.isOpen && this.focusTrapActive`. If the component is destroyed while `isOpen === true` (e.g., the parent `HeaderComponent` is torn down by a route change), `ngAfterViewChecked` never runs with `isOpen === false`. The `keydown` listener remains attached to the detached native element. Fix:

```typescript
implements AfterViewChecked, OnDestroy {
  ngOnDestroy(): void {
    this.deactivateFocusTrap();
  }
}
```

## ProductDetailComponent change detection gap

The component imports and orchestrates `ProductGalleryComponent`, `ProductCustomizationComponent`, `DesignUploadComponent`, and `ProductPricingComponent` — all marked `OnPush`. The parent, however, uses Angular's default strategy. Template expressions like `customizationSummary` (which calls `this.customizationService.calculateCustomizationTotal(...)`) re-execute on every CD cycle. With `OnPush` and computed signals, this work would only happen when a dependency signal changes.

The component already uses `signal()` for all state and `takeUntilDestroyed` for subscriptions, so adding `OnPush` requires no other refactoring — the template already reads from signals via function calls (`loading()`, `product()`, `featureControl()`, etc.).
