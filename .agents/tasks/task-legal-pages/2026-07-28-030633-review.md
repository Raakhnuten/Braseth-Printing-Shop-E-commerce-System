# Static legal pages for Privacy Policy, Terms of Service, and Cookies

Three standalone Angular components provide static legal content at `/privacy-policy`, `/terms-of-service`, and `/cookies`. Each follows the existing public-page pattern: lazy-loaded route, `PageHeaderComponent` with breadcrumbs, BEM-named SCSS using design tokens. The footer's dead `href="#"` links are replaced with `routerLink` directives pointing to these new routes. The wildcard `**` route remains last, preserving catch-all behavior.

**Watch for:** Duplicated SCSS across all three components (~80 identical lines each) that will drift over time (confirmed). The cookies component adds a `__subheading` rule absent from the other two, meaning styling is already inconsistent across the set (confirmed).

## High-level view

Three leaf components with no logic, no services, no state slot into the existing route tree as siblings of the auth routes, before the wildcard. The architectural fit follows the same pattern as existing pages like `categories` and `page-not-found`.

The style duplication is the only structural concern. The three SCSS files contain the same `.legal-page` block (82–95 lines) copy-pasted with minor variance, which creates a maintenance surface that will diverge silently as individual pages are edited. A shared `_legal-page.scss` partial imported by each component would eliminate this.

## Duplicated SCSS creates a maintenance surface

The privacy-policy and terms-of-service SCSS files are byte-for-byte identical (sha `1f780e2ca34d998216cb3f9a42e4c280`). The cookies SCSS adds 13 lines for `.legal-page__subheading` but is otherwise the same block. Any visual tweak to the legal page layout (spacing, border color, responsive breakpoints) needs to be applied in three files.

Angular standalone components with `styleUrl` support `@use` for shared SCSS partials. The natural fix:

```
src/app/styles/_legal-page.scss    ← shared .legal-page block + subheading
src/app/features/public/cookies/cookies.component.scss          ← @use '../../../styles/legal-page'
src/app/features/public/privacy-policy/privacy-policy.component.scss  ← same
src/app/features/public/terms-of-service/terms-of-service.component.scss  ← same
```

This reduces each component SCSS to one `@use` statement plus any page-specific overrides (currently none).
